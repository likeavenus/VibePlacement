# VibePlacement

Рабочий MVP платформы для тех, кто хочет создать игру, и креаторов, которые помогают её собрать. Продукт переименован из Kadrift; существующая рабочая папка сохранена: `R:\work\kadrift`.

## Локальный запуск

Node.js 22.12+, npm. Все зависимости, кеши, профили браузера и артефакты находятся на R:.

```powershell
cd R:\work\kadrift
$env:TEMP='R:\work\kadrift\.tmp'
$env:TMP='R:\work\kadrift\.tmp'
New-Item -ItemType Directory -Force .tmp | Out-Null
npm.cmd install
npm.cmd run dev
```

Frontend: http://localhost:5186. Запасной порт: `npm.cmd run dev -- --port 5187`.

Backend-каркас: установить зависимости в `server/`, затем `npm.cmd run dev:api` из корня. Swagger: http://localhost:5188/api/docs. Health: http://localhost:5188/api/v1/health. API запускается через ts-node без сборки; PostgreSQL пока не требуется для двух системных endpoints.

Тестовая версия: https://likeavenus.github.io/VibePlacement/. Для публикации на GitHub Pages используется только целевая сборка `npm.cmd run build:pages`. На Selectel ничего не изменялось; `build:selectel` оставлен для будущего деплоя.

Pages использует базовый путь `/VibePlacement/` и HashRouter: прямые ссылки имеют вид `/#/projects/letters-novel`. Каталог `dist/` публикуется в ветку `gh-pages`, исходники находятся в `main`. Настройка Pages: `node scripts/github-pages.mjs enable`, проверка статуса: `node scripts/github-pages.mjs status`. Учётные данные GitHub берутся из Git Credential Manager и не сохраняются в проекте.

## Пользовательские пути

### Автор игры

`Начать здесь → Создаю игру → Создать игру → Задачи игры → Добавить задачу`.

Из рабочего пространства доступны подбор ассетов и набор команды. Объявление наследует название, идею, движок и жанр игры, сохраняет `gameId` и ведёт обратно к её задачам. Повторный переход открывает существующее объявление.

В игре указаны идея, движок, жанр и бюджет. Таблица содержит сущности, направление, требования, список нужных анимаций, стоимость, сроки, исполнителя, статус и материал. Есть поиск, фильтр, редактирование, удаление с подтверждением и предупреждение о превышении бюджета. Для принятия задачи требуются исполнитель и материал. Готовый ассет можно приобрести в демо-режиме и добавить в игру.

### Поиск команды и договорённости

`Найти проект → Жанр / этап / роль → Страница проекта → Условия участия → Отклик`.

У игры есть отдельная страница с описанием, ближайшей целью, платформой, движком, бюджетом или пулом RevShare и открытыми ролями. Шесть примеров включают RPG, приключения, платформер, стратегию и визуальную новеллу. Фильтры сохраняются в URL.

Автор может редактировать базовый шаблон или свой текст условий по шести разделам, сохранять новые версии и экспортировать JSON/TXT. Отклик сохраняет точную копию выбранной версии и SHA-256 для проверки целостности. Это локальные черновики: личность, подписание, доставка автору и достоверное время не подтверждаются. Шаблон не проверен юристом. Рабочая среда содержит публичные HTTPS-ссылки на репозиторий, чат и документы.

### Креатор

`Начать здесь → Я креатор → Опубликовать работу → Проверить превью → Публикация`.

Управление работами и продажами находится в «Мои публикации», приобретённые ассеты — в «Мои покупки».

Восемь направлений используют общий справочник `src/data/categories.ts`: 3D, 2D, Spine, моушн, UX/UI, ИИ-видео, звук и сценарии. Код, вайбкодинг и шейдеры исключены из публикаций и форм. Форматы предложений: готовый ассет, услуга на заказ или портфолио. Пользовательские файлы сохраняются в IndexedDB, метаданные в localStorage. Работа появляется в ленте, профиле и мастерской после проверки. Есть комментарии, библиотека приобретённых ассетов и экран продаж с комиссией.

### Файлы и проверка

| Направление | Файлы |
| --- | --- |
| 3D | Один GLB 2.0, FBX или OBJ; до 1 млн вершин |
| 2D, UX/UI | До 8 PNG, JPG, WebP; галерея экранов |
| Spine | JSON 4.2 + atlas + PNG |
| Моушн | MP4, WebM или GIF |
| ИИ-видео | MP4 или WebM |
| Звук | WAV, MP3, OGG, FLAC |
| Сценарии | TXT, Markdown, JSON редактора сцен; UTF-8 |

Форма меняет `accept`, подсказку, число файлов и просмотрщик по выбранному направлению. При смене направления старый результат проверки сбрасывается. Проверяются расширения, сигнатуры, декодирование изображений/медиа, структура сценария и геометрия 3D. PNG под именем FBX не принимается. Общий лимит: 30 МБ. Изображения: до 8192 px по стороне и 32 млн пикселей. 3D принимает встроенные ресурсы; внешние текстуры/MTL не поддержаны, для них нужен экспорт в GLB. Поддержка аудио/видео зависит от кодеков браузера. ZIP, PSD, FIG, AEP, PDF и DOCX на этом этапе не принимаются.

Это клиентская валидация локального MVP. При подключении upload API сервер обязан повторно проверять содержимое в изолированном worker, независимо от результата браузера.

### Сценарии

Редактор: логлайн, жанр, сцены с местом, действием, персонажем, репликой и переходом. Сцены можно добавлять, переставлять и удалять; удаление очищает ссылки на сцену. До 30 сцен и 100 000 знаков. JSON сохраняет структуру; TXT/Markdown импортируются как текстовые фрагменты без исполнения HTML. Просмотр: обложка, рукопись с оглавлением и навигацией, список связей сцен.

### Навигация и текст

Старт `/` содержит два пути: автор игры и креатор. Каталог `/market` и поиск проектов `/discover` разделены; старые ссылки `/?category=…` и `/?mode=projects` перенаправляются с сохранением фильтров. На первом посещении открывается гайд из трёх шагов с выбором пути и подсветкой настоящих кнопок. Завершение или пропуск сохраняется в `vibeplacement:guide-v1`; кнопка помощи в шапке запускает гайд повторно. Есть Escape, удержание фокуса, блокировка фоновых действий, мобильное кадрирование подсветки и reduced motion.

Страницы загружаются через React lazy/Suspense. Верхняя полоса появляется при переходе и остаётся до готовности маршрута; на время загрузки есть скелетон. Навигация не задерживается ради анимации, учтён reduced motion. Основной текст 16 px, служебный от 14 px, названия работ 18 px, рукопись 17–18 px. Сетка и формы адаптированы под эти размеры.

## Spine-вьюер

PixiJS 8 + официальный runtime Spine 4.2. Настоящий скелетный рендер, выбор всех анимаций из файла, play/pause, скорость, цикл, перемотка, расширенный просмотр, скины, масштаб, фон и отображение костей. Автоматическое кадрирование учитывает всю выбранную анимацию. Вне экрана вьюер выгружается.

Для публикации: один экспорт `.json` версии 4.2, один `.atlas` и все его `.png`. `.skel` и другие версии пока не поддержаны. Лимиты: 30 МБ, 20 файлов, до 8 текстурных страниц, 4096 × 4096 на страницу. Не хватает текстуры или неверная версия — публикация блокируется. После проверки структуры требуется успешный рендер превью.

Демо Spineboy принадлежит Esoteric Software, не продаётся и не выдаётся за авторский ассет. Лицензионные условия runtime необходимо выполнить перед коммерческим запуском. См. [лицензию](public/assets/spine/LICENSE.txt) и [атрибуцию](public/assets/CREDITS.md).

## Стек

| Слой | Решение |
| --- | --- |
| Web | React 19, TypeScript, Vite, React Router |
| UI | Tailwind CSS 4, Lucide, локальные Golos Text и JetBrains Mono |
| 3D | Three.js, R3F, Drei |
| Скелетная анимация | PixiJS 8, Spine runtime 4.2 |
| Аудио | WaveSurfer |
| Изображения | react-zoom-pan-pinch, сравнение до/после |
| Сценарии | Редактор сцен, Zod, режим чтения |
| Локальные данные | Zod, localStorage, IndexedDB через idb |
| Backend | NestJS, REST/OpenAPI, PostgreSQL/Prisma |
| Хранилище при деплое | Selectel S3; пока только архитектурное решение |

**GraphQL пока не используем.** Для одного web-клиента и известных экранов REST проще; агрегированный endpoint рабочего пространства устраняет необходимость множества запросов. NestJS-сервисы позволят добавить GraphQL позже без смены базы и бизнес-логики. Подробности: [docs/backend.md](docs/backend.md).


## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run typecheck:api
npm.cmd run verify
node scripts/verify-refinements.mjs
node scripts/verify-journeys.mjs
```

Проверка браузера использует установленный Chrome, отдельный профиль на R: и проверяет пиксели/движение Spine, паузу/перемотку, импорт, сохранение публикаций, комментарии, таблицу игры, библиотеку, покупки и ширины 320–1920 px. Нужен работающий dev-сервер. Снимки и отчёт: `artifacts/`. Тестовый профиль очищается после прогона; пользовательский браузер не затрагивается.

`npm.cmd --prefix server run db:validate` валидирует схему; DATABASE_URL из `server/.env.example` должен быть установлен. Миграции и генерация клиента не запускались. Для будущей миграции также описаны обязательные ограничения сумм, рейтинга и процентов в `docs/backend.md`.

## Границы текущего этапа

Frontend остаётся локальным MVP с фиксированным демопользователем Денис / dev. Состояние между браузерами не синхронизируется. Backend пока каркас и схема, не подключён к frontend. Авторизация, отправка заказов, реальная модерация, платежи и выплаты требуют следующего этапа. Финансовые действия явно помечены как демо, коммерческая лицензия ими не выдаётся. Комиссия 10% — тестовая настройка, не утверждённый тариф. Комментарии не влияют на рейтинг; публичный рейтинг пока моковый и в production должен рассчитываться только по завершённым сделкам.

Реализована базовая i18n-структура, EN выключен до полного перевода. Модель дома, пиксельный арт и аудио остаются демонстрационными. Политика хранения файлов соблюдена: вся работа в `R:\work\kadrift`, системные файлы на C: только читаются.
