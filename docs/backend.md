# VibePlacement: backend decision

## Решение

NestJS 11 + PostgreSQL + Prisma 6. REST/OpenAPI для первого backend-релиза. Медиа: приватное Selectel S3, публичные превью отдельно. Модульный монолит; отдельные сервисы и Redis пока не нужны.

GraphQL подходит для связанных сущностей платформы, но сейчас один web-клиент и несколько фиксированных экранов. `GET /games/:id/workspace` может вернуть задачи, бюджет и участников одним запросом, поэтому GraphQL пока не даёт достаточного выигрыша относительно усложнения авторизации полей, лимитов запросов и кеширования. При появлении нескольких клиентов можно добавить GraphQL поверх тех же прикладных сервисов. Загрузка файлов и webhook платежей в любом случае остаются HTTP.

## Что уже реализовано

`server/` содержит запускаемый NestJS API: `GET /api/v1/health`, `GET /api/v1/capabilities`, Swagger UI `/api/docs`, валидация DTO и CORS для локального frontend. Полная начальная схема PostgreSQL в `server/prisma/schema.prisma`. Business API, авторизация и реальные платежи пока не включены. Frontend использует localStorage/IndexedDB и честно обозначает локальные действия.

## Модули следующего backend-этапа

| Модуль | Ответственность |
| --- | --- |
| Identity | OIDC/session, роли, профиль, проверки владельца |
| Games | Игра, участники, сущности, техническое задание, бюджет, статусы |
| Publications | Работа, тип предложения, лицензия, модерация |
| Assets | Подписанные S3 URL, проверка экспорта, версии, миниатюры |
| Community | Комментарии, жалобы, модерация; отзывы только после сделки |
| Commerce | Заказ, договорённости, платежи, доступ к купленному |
| Accounting | Неизменяемый журнал начислений, комиссия, возвраты, выплаты |

## API-контракты следующего этапа

Направления: MODEL, ART, ANIMATION, MOTION, UX_UI, AUDIO, WRITING, VIDEO. GAME_CODE удалён из начальной схемы до первой миграции. Клиентский справочник: `src/data/categories.ts`. Валидация локального frontend проверяет содержимое файла, но не заменяет серверную проверку при подключении S3.

- `POST /games`, `GET /games`, `GET /games/:id/workspace`.
- `POST /games/:id/tasks`, `PATCH /games/:id/tasks/:taskId` с версией записи; сервер проверяет принадлежность задачи игре и доступ к игре.
- `POST /tasks/:id/orders`, `POST /orders/:id/deliveries`, `POST /orders/:id/accept`. Финансовые статусы не меняются через общий PATCH.
- `POST /publications`, `GET /publications?kind=ANIMATION`, `GET /publications/:id`.
- `POST /publications/:id/comments`, `DELETE /comments/:id` только автору или модератору.
- `POST /assets/upload-intents`, `POST /assets/:id/finalize`; ограничение размера, MIME, manifest и проверка в изолированном worker. Приватные исходники не отдаются по публичным URL.
- `POST /checkout` с idempotency key. Сумма и комиссия определяются сервером по версии предложения. Snapshot условий сохраняется в заказе.
- `POST /webhooks/payments/:provider`: проверка подписи, дедупликация providerEventId, транзакционное начисление и выдача Entitlement. Переход браузера на success URL не подтверждает платёж.
- `GET /library`, `POST /entitlements/:id/download-url`: доступ после подтверждённой оплаты, короткоживущие S3-ссылки.

Все суммы — целые minor units (копейки), не float. Публичный рейтинг вычисляется из отзывов к завершённым заказам. При миграции добавить CHECK constraints: rating 1..5, суммы >=0, комиссия <= суммы, basis points 0..10000; сумму RevShare по игре проверять транзакционно под блокировкой игры. Редакторский статус задачи не является подтверждением оплаты.

## Монетизация

Первый сценарий: комиссия с продаж готовых ассетов и выполненных заказов. В локальном UI используется тестовое значение 10%, это не утверждённый тариф. Платное расширенное рабочее пространство можно добавить после проверки спроса. До настоящих выплат нужно выбрать платёжного провайдера, поддерживающего маркетплейс и расчёты с исполнителями, правила возвратов и юридическую модель. Платформа не должна выдавать обычное хранение денег за escrow.

## Локальный запуск без сборки

```powershell
cd R:\work\kadrift\server
$env:TEMP='R:\work\kadrift\.tmp'
$env:TMP='R:\work\kadrift\.tmp'
npm.cmd install
npm.cmd run dev
```

Swagger: http://localhost:5188/api/docs. `npm.cmd run typecheck` не создаёт сборку. `npm.cmd run db:validate` проверяет схему (укажите DATABASE_URL из `.env.example`). PostgreSQL не нужен для текущих системных endpoints. Для бизнес-функций сначала подключить PostgreSQL, настроить auth и применить миграции; в текущей итерации база не создавалась и данные на Selectel не изменялись.
